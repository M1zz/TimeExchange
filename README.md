# 시간 환전소 (TimeExchange)

시간을 **색으로** 기록하고, 색마다 다른 방식으로 돈을 붙이는 iOS 앱.

한 주를 여덟 칸 × 이레의 격자로 칠한다. 그 다음 칸마다 전표를 붙인다.
색이 곧 계정과목이고, 색마다 전표가 다르게 생겼다. 그 다름이 이 앱의 전부다.

## 다섯 가지 색

| 색 | 이름 | 장부에서 | 전표에 들어가는 것 |
|---|---|---|---|
| 🟡 | 팔았다 | 실현 수익 | 입금액 + 무엇을 팔았나 |
| 🔵 | 심었다 | 자산에 심은 시간 | **태그만.** 금액 칸이 없다 |
| 🔴 | 누렸다 | 배당의 원가 | 쓴 돈만 |
| 🟢 | 돌봤다 | 운영비 / 출금 | 운영비 + 이 칸을 사는 거래 |
| ⬛ | 안개 | — | **전표를 붙일 수 없다** |

### 파랑에 금액 칸이 없는 이유

심은 시간을 매일 평가하면 아직 값이 없는 일을 그만두게 된다.
파랑은 오늘 0원이 정상이다. 금액 칸이 없는 것은 실수가 아니라 원칙이다.

수익이 실현되면 «주간 읽기»의 회수 기록에 태그와 금액을 넣는다.
그 태그의 파란 칸 **전체**로 소급 배분되어 칸당 회수액이 갱신된다.

### 빨강에 원가만 붙는 이유

누린 시간의 가치는 계산하지 않는다. 가격이 붙는 순간 누리는 능력이 죽는다.
원가만 안다.

### 안개에 전표를 붙이지 않는 이유

기억이 안 나면 누수고, 판단이 안 서면 미결이다.
여기에 돈을 붙이는 순간 이 앱은 죄책감 장치가 된다. 안개는 개수만 센다.

## 월급은 칸에 붙지 않는다

월급은 칸마다 입금되지 않으므로 월급 칸에는 금액을 적지 않는다. 노랑 전표에서
«이 칸은 월급에서 나옵니다»를 켜면 금액란이 사라지고, 그 달의 실수령액이 그 달의 월급 칸
전체로 배분된다. 파랑의 회수와 같은 구조다. 달 중간이면 경과일수만큼만 안분한다.

그래서 **출근한 시간을 전부 노랑으로 칠할 필요가 없다.** 회사에서 배운 시간은 파랑,
회의와 잡무는 초록, 기억나지 않는 시간은 안개다. 노랑이 줄면 남은 노랑의 단가는 올라간다.

여기서 시급이 두 개가 된다. 둘을 섞지 않는다.

| | 계산 | 쓰임 |
|---|---|---|
| **구속 시급** | 월급 ÷ (근무 + 통근) 전체 | **출금 판단에 쓴다** |
| **판 시간 시급** | 월급 ÷ 실제로 노랑으로 칠한 시간 | 관측만 한다 |

40시간 매여 100만원을 받는데 판 시간이 20시간이면 판 시간 시급은 5만원이다. 밀도가 두 배라는
뜻이고 좋은 신호다. 하지만 이 5만원으로 출금을 판단하면 안 된다. 회사는 판 20시간이 아니라
매인 40시간에 돈을 주므로, 5만원을 쥐려면 여전히 네 시간을 앉아 있어야 한다. 시급을 높게 잡으면
모든 출금이 이득으로 보이는 것은 통근을 빼는 것과 같은 함정이다.

(예외: 한 시간 더 팔면 돈이 더 들어오는 사람 — 프리랜서 — 에게는 판 시간 시급이 진짜 기준이다.
월급쟁이는 한 시간 더 앉아 있어도 추가 수입이 0이라 그렇지 않다.)

## 초록이 환전소에 닿는 지점

가사 대행이 이 거래다. 초록 칸의 전표에서 지불액을 넣고 «심었다로/누렸다로»를 고르면,
그 칸이 실제로 새 색으로 바뀌고 출금 거래가 하나 생긴다.
주간 읽기에는 이렇게 남는다.

```
화 저녁 칸을 45,000원에 🟢 → 🔵
번÷산 1.24 · 순증 +0.6h
```

출금의 판단에는 **노동 환율만** 쓴다. 나머지 색에는 이 숫자가 닿지 않는다.

```
번 ÷ 산 > 1   내 시급보다 싸게 샀다 → 시간이 실제로 늘어남
번 ÷ 산 = 1   시간이 이동만 함
번 ÷ 산 < 1   비싸게 샀다 → 다른 날에서 빌려옴
```

## 심은 시간은 무엇으로 돌아오는가

시간을 넣었으면 무언가로 나와야 한다. 나오는 형태는 하나가 아니다.

| | 무엇 | 어떻게 적나 |
|---|---|---|
| **돈으로** | 그 자산에서 수익이 실현됐다 | 회수액 → 그 태그의 파란 칸 전체로 소급 배분 |
| **시간으로** | 도구를 만들었더니 같은 일에 시간이 덜 든다 | 앞으로 안 써도 되는 시간 |
| **배당으로** | 내가 만든 것 덕분에 즐거운 시간이 생겼다 | 빨강 칸에 그 자산 이름을 잇는다 |

배당에는 값을 매기지 않고 **세기만** 한다. 내가 만든 것 덕분에 즐거웠던 시간에 가격을 붙이면
빨강에 가격을 붙이지 않는 이유가 그대로 무너지기 때문이다.

그리고 네 번째, **아무것도 돌아오지 않는 경우**. 그래서 «접음»이 회수의 한 종류로 들어가 있다.
접은 것을 적지 않는 장부는 성공한 것만 기억하고, 그러면 남은 자산의 숫자도 못 믿게 된다.

«자산» 탭이 이것을 태그별로 한 장씩 보여준다. 셋을 더하지 않고 나란히 두며, 확실하게 말하는
것은 하나뿐이다 — **무엇이 아직 아무것도 돌려주지 않았는가.**

회수가 오기 전에는 시급을 계산하지 않는다. 계산하면 반드시 0원이 나오고, 그 0원이 아직 값이
없는 일을 그만두게 만든다.

## 주간 읽기는 합산하지 않는다

다섯 줄이고 총점이 없다. 실측 시급 / 태그별 회수 / 배당 원가 / 출금 내역 / 안개 개수.

판 시간, 심은 시간, 누린 시간, 돌본 시간은 단위가 다르다.
하나의 점수로 합치는 순간 올릴 대상이 생기고, 사람은 점수를 올리려고 삶을 바꾼다.
재무제표가 매출과 자산과 비용을 한 칸에 더하지 않는 것과 같은 이유로, 나란히만 둔다.

노랑은 유일하게 돈이 관측되는 색이다. 칸이 쌓이면 추정 시급이 실측 시급이 된다.
태그별로 단가가 갈리면 **어느 노랑을 줄일지**가 거기서 나온다.

## 금액은 한글로 되읽어 준다

`120000`을 치면 아래에 `십이만원`이 뜬다. 0을 하나 더 치거나 덜 친 실수는 숫자를 다시 봐서는
잘 안 잡히고, 소리내어 읽어야 잡힌다. 전표의 모든 금액 칸과 회수액, 환율 설정의 월급·자산에
붙어 있다. (`Fmt.korean`)

## 라이트·다크

시스템 외형을 따라간다. 팔레트는 `Palette`에 두 벌로 정의되어 있고, 네 계정과목의 색은
두 모드에서 같은 색으로 읽히도록 명도만 조정한다. 색 위에 얹는 글자(`Palette.ink`)는
배경이 두 모드에서 같으므로 고정값이다.

## 모드 대신 «손에 든 것»

칠하기 모드 / 전표 모드 같은 스위치는 없다. 대신 색칠판 아래 팔레트에서 무엇을 집었는지가
동작을 정한다.

- **아무것도 안 들었을 때** (기본) — 칸을 누르면 전표가 열리고, 색은 그 안에서 고른다
- **물감을 들었을 때** — 칸을 문질러 칠한다. 여러 칸을 한 번에 쓸 수 있다

같은 물감을 다시 누르면 내려놓는다. 모드는 안 보이지만 손에 든 물감은 보인다.

## 개념 페이지

색 이름만 보면 이 앱은 그냥 예쁜 시간표다. «개념» 탭에 왜 색마다 전표가 다르게 생겼는지,
왜 네 숫자를 더하지 않는지, 각 색의 함정이 무엇인지를 모아 두었다.

## 색을 바꾸면 전표가 지워진다

계정과목이 바뀌었는데 전표를 이월하는 것은 회계상 틀리다. 그래서 리셋한다.

시트 안에서 색을 바꾸면 그 자리에서 경고가 뜨고, 저장을 눌러야 실제로 지워진다.
원래 색으로 되돌리면 붙어 있던 전표도 그대로 돌아온다.
(`LedgerSheet.willDiscardLedger` / `colorChanged`)

## 환율은 직접 입력하지 않는다

시급을 손으로 찍으면 사람은 자기 시간을 후하게 잡고, 그러면 모든 출금이 이득으로 보이는
자기합리화 도구가 된다. 그래서 월급에서 도출한다.

```
노동 환율 = 월 실수령액(세후) ÷ (월 근무시간 + 월 통근시간)
```

분모에 **통근을 포함**하는 것이 핵심이다. 급여에 잡히지 않지만 회사 때문에 쓰는 시간이므로
판 시간이 맞다. 통근을 빼면 시급이 약 19% 부풀려진다.

```
자산 환율 = 자산 × 연 기대수익률 ÷ 8,760h
```

달력 시간으로 나누는 이유는 자산이 자는 동안에도 일하기 때문이다.
이 값은 참고 지표일 뿐이며, **출금 순증 계산에는 노동 환율만 사용한다.**

## 화면

- **색칠판** — 주간 격자와 팔레트. 물감 없이 누르면 전표, 물감을 들면 칠하기
- **주간 읽기** — 다섯 줄
- **자산** — 태그별 장부. 심은 시간이 무엇으로 돌아왔는지
- **개념** — 색이 무엇을 뜻하고 왜 그렇게 생겼는지
- **환율** — 월급·근무시간·자산 입력, 도출된 시급 확인

| `SeedData.swift` | 첫 실행 데모 한 주 |

## 기술

- SwiftUI + SwiftData, iOS 17.0+
- 거래 시점의 환율은 `Exchange.myRateAtTime`에 스냅샷으로 저장된다.
  나중에 시급이 바뀌어도 과거 거래의 판단은 그대로 남는다.

## 빌드

```bash
xcodebuild -project TimeExchange.xcodeproj \
           -scheme TimeExchange \
           -destination 'platform=iOS Simulator,name=iPhone 17' \
           build
```

클론 후 `DEVELOPMENT_TEAM`을 본인 것으로 바꿔야 실기기 빌드가 된다.
